Unir tablas con INNER JOIN

Los datos de una biblioteca viven repartidos en varias tablas. INNER JOIN las vuelve a juntar: combina cada fila con las filas de la otra tabla que tienen la misma clave y descarta las que no tienen pareja.

1 · LA IDEA

Combinar todo, quedarse con lo que coincide

En BiblioUTU cada libro guarda el número de su autor en la columna id_autor (clave foránea), y la tabla autor guarda el nombre con ese mismo número como clave primaria. Así el nombre de Horacio Quiroga se escribe una sola vez, aunque tenga varios libros.

Pensalo en dos movimientos. Primero se arma cada combinación posible: 5 libros × 4 autores = 20 parejas. Después el ON se queda solo con las parejas donde los números coinciden.

20 combinaciones → 4 cumplen el ON

2 · DOS TABLAS · HERENCIA

Persona y Alumno: el JOIN reconstruye la herencia

Un alumno es una persona: tiene código y nombre como cualquier persona, y además teléfono y grupo. En el MER eso se dibuja como una generalización. Al pasar al MR, alumno hereda la clave cod de persona, y para ver al alumno completo hay que volver a unir las dos tablas con un INNER JOIN.

Modelo Entidad-Relación

El triángulo ES marca la generalización: PERSONA es la entidad general y ALUMNO la especializada. ALUMNO no repite cod ni nombre: los hereda de PERSONA y solo agrega tel y grupo.

MR

Modelo Relacional

PERSONA (cod, nombre)

ALUMNO (cod, tel, grupo)

cod se hereda de PERSONA hacia ALUMNO: es PK y FK a la vez

Cada alumno usa el mismo cod que su fila en persona, así que la relación es 1 a 1. Una persona puede no ser alumno (un docente, por ejemplo), pero no hay alumno sin persona. Subrayado: clave primaria. Cursiva y #: clave foránea.

alumno.cod → persona.cod. En alumno, cod no lleva AUTO_INCREMENT: el número lo pone persona y alumno lo copia. Con ON DELETE CASCADE, si se borra una persona, su fila en alumno se borra sola.

SQL

Implementación

CREATE TABLE persona (
  cod    INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(80) NOT NULL
);
CREATE TABLE alumno (
  cod   INT PRIMARY KEY,
  tel   VARCHAR(20),
  grupo VARCHAR(20) NOT NULL,
  FOREIGN KEY (cod) REFERENCES persona(cod)
    ON DELETE CASCADE
);
-- consultar: el alumno completo = persona + alumno
SELECT p.cod, p.nombre, a.tel, a.grupo
FROM persona p
INNER JOIN alumno a ON p.cod = a.cod;

La consulta, fila por fila

Para cada fila de persona, la base recorre alumno y compara cod. Solo las personas que también son alumnos llegan al resultado. Tocá Reproducir o avanzá con Paso.

SELECT p.cod, p.nombre, a.tel, a.grupo
FROM persona p
INNER JOIN alumno a
  ON p.cod = a.cod;

3 · SINTAXIS

Las partes de la consulta

SELECT l.titulo, a.nombreQué columnas querés ver. Con el alias delante sabés de qué tabla sale cada una.
FROM libro lLa primera tabla. La l es un alias: un nombre corto para no escribir libro. cada vez.
INNER JOIN autor aLa tabla que se suma. En MySQL JOIN solo, sin INNER, hace exactamente lo mismo.
ON l.id_autor = a.id_autorLa condición de unión: clave foránea de un lado, clave primaria del otro.
WHERE a.pais = 'Uruguay'Opcional. Filtra el resultado ya unido, como en cualquier SELECT.
ORDER BY a.nombreOpcional. Ordena el resultado final.

Sin alias

SELECT libro.titulo, autor.nombre
FROM libro
INNER JOIN autor
  ON libro.id_autor = autor.id_autor;

Con alias, filtro y orden

SELECT l.titulo, a.nombre
FROM libro l
JOIN autor a ON l.id_autor = a.id_autor
WHERE a.pais = 'Uruguay'
ORDER BY a.nombre;

4 · TRES TABLAS

La tabla del medio conecta las otras dos

Un préstamo dice quién se llevó qué libro y cuándo, pero solo con números. Para leerlo con nombres hay que unir prestamo con socio y con libro. Con tres tablas se escriben dos JOIN: la base une las dos primeras y al resultado le suma la tercera.

MERconceptual→MRlógico→FísicoMySQL→SQLimplementación
MER

Modelo Entidad-Relación

Un socio pide muchos libros y un libro lo piden muchos socios: relación N:M. La fecha es atributo de la relación, no de una entidad. En el MER no existe PRESTAMO como entidad.

MR

Modelo Relacional

SOCIO (id_socio, nombre, grupo)

LIBRO (id_libro, titulo, anio, id_autor)

PRESTAMO (id_prestamo, id_socio, id_libro, fecha)

el rombo N:M se convierte en la tabla PRESTAMO, que hereda id_socio y id_libro

Una relación N:M siempre genera una tabla nueva con las claves de las dos entidades y los atributos de la relación. Se agrega id_prestamo como clave propia porque un socio puede pedir el mismo libro más de una vez.

SQL

Implementación

CREATE TABLE socio (
  id_socio INT AUTO_INCREMENT PRIMARY KEY,
  nombre   VARCHAR(80) NOT NULL,
  grupo    VARCHAR(20)
);
CREATE TABLE prestamo (
  id_prestamo INT AUTO_INCREMENT PRIMARY KEY,
  id_socio    INT NOT NULL,
  id_libro    INT NOT NULL,
  fecha       DATE NOT NULL,
  FOREIGN KEY (id_socio) REFERENCES socio(id_socio),
  FOREIGN KEY (id_libro) REFERENCES libro(id_libro)
);
-- consultar: una FK por cada ON
SELECT s.nombre, l.titulo, p.fecha
FROM prestamo p
INNER JOIN socio s ON p.id_socio = s.id_socio
INNER JOIN libro l ON p.id_libro = l.id_libro;

5 · ERRORES COMUNES

Tres errores que aparecen en todas las clases

Olvidar el ON

SELECT titulo, nombre
FROM libro, autor;

Sin condición se devuelven todas las combinaciones: el producto cartesiano. Con 5 libros y 4 autores son 20 filas, y 16 no tienen sentido. Es la cuadrícula de la sección 1 sin filtrar.

Columna ambigua

SELECT titulo, id_autor
FROM libro l
JOIN autor a ON l.id_autor = a.id_autor;
Error Code: 1052. Column 'id_autor' in field list is ambiguous

id_autor existe en las dos tablas. Escribí l.id_autor o a.id_autor.

Unir por la columna equivocada

SELECT l.titulo, a.nombre
FROM libro l
JOIN autor a ON l.id_libro = a.id_autor;

No da error, pero sí un resultado falso: «La tregua» (id_libro 2) aparece escrita por Juana de Ibarbourou (id_autor 2). El ON siempre une la FK con la PK a la que apunta.

Ejercicios

Herencia · Nombre y teléfono de los alumnos de 2.º BT (2 tablas) 
SELECT p.nombre, a.tel
FROM persona p
INNER JOIN alumno a ON p.cod = a.cod
WHERE a.grupo = '2.º BT';

Resultado esperado: Ana Silva y Bruno Méndez. El nombre sale de persona y el teléfono de alumno.

A · Título y año de cada libro con el país de su autor (2 tablas) 
SELECT l.titulo, l.anio, a.pais
FROM libro l
INNER JOIN autor a ON l.id_autor = a.id_autor;

Resultado esperado: 4 filas. «Atlas escolar» no aparece porque no tiene autor.

B · Nombre del socio y fecha de cada préstamo, del más reciente al más viejo (2 tablas) 
SELECT s.nombre, p.fecha
FROM prestamo p
INNER JOIN socio s ON p.id_socio = s.id_socio
ORDER BY p.fecha DESC;

Resultado esperado: 4 filas, empezando por Matías Rodríguez el 2026-10-12.

C · Títulos que pidió prestados Lucía Pérez (3 tablas + WHERE) 
SELECT l.titulo, p.fecha
FROM prestamo p
INNER JOIN socio s ON p.id_socio = s.id_socio
INNER JOIN libro l ON p.id_libro = l.id_libro
WHERE s.nombre = 'Lucía Pérez';

Resultado esperado: «La tregua» y «Las lenguas de diamante».

D · Desafío: quién se llevó libros de autores uruguayos (4 tablas) 
SELECT s.nombre, l.titulo, a.nombre AS autor
FROM prestamo p
INNER JOIN socio s ON p.id_socio = s.id_socio
INNER JOIN libro l ON p.id_libro = l.id_libro
INNER JOIN autor a ON l.id_autor = a.id_autor
WHERE a.pais = 'Uruguay';

La regla se mantiene: con N tablas hacen falta N − 1 JOIN. Con AS le ponés otro nombre a una columna del resultado.
